## Corrections faites pendant cet audit

- La confirmation d’une réservation publique était masquée après sauvegarde, car le brouillon vidé n’avait plus de véhicule sélectionné. L’écran de confirmation est maintenant vérifié avant cette garde dans `AdminCreateQuote.tsx`.
- Le conteneur des onglets admin mobiles pouvait élargir la page. Une largeur minimale nulle a été ajoutée ; le parcours E2E ne détecte plus de débordement horizontal.
- Le banc navigateur attend désormais les éléments réels de chaque page admin avant de capturer les écrans.
- L’accueil suit à présent l’ordre et la disposition des véhicules de la référence ; les prix restent issus des réglages SQL pour ne pas écraser les montants saisis.
- La table Clients reprend la largeur minimale de 900 px de la référence ; les noms ne sont pas tronqués et la table peut encore défiler si leur contenu l’exige.
- La comptabilité affiche maintenant les hypothèses et objectifs sans confirmation préalable. La simulation indique explicitement qu’elle n’est pas un solde bancaire ; le journal réel demeure séparé et fondé sur ses écritures.
- Les quatre actions de corbeille des réservations sont isolées dans un service d’application dédié sans changer leurs contrôles d’accès ni leurs erreurs.

## Conclusion et limites

Les écarts de présentation relevés sur l’accueil et la comptabilité ont été corrigés au niveau du code. L’égalité des tarifs dépend encore des valeurs présentes dans la base : elles ne sont pas remplacées par les valeurs d’exemple du HTML. L’application garde PostgreSQL, l’authentification par rôle et les routes additionnelles demandées dans les échanges précédents, donc ces comportements d’infrastructure ne reproduisent pas le stockage navigateur du prototype. Le HTML source de référence plante lui-même sans correction temporaire ; les comparaisons d’écrans ont donc utilisé une copie de diagnostic. Les scénarios non listés comme testés dans le tableau restent à parcourir avant toute affirmation d’équivalence fonctionnelle exhaustive. Le navigateur et la base n’ont pas été rejoués après les corrections de cette session, et aucun test n’a été exécuté contre la base de production.
